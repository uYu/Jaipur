# DMC + MCTS 对齐审查

审查对象：本目录提前停止的 1 秒对照赛；对照 [AI 算法说明](../../docs/AI_ALGORITHM.md)、[DMC 实验交接](../../docs/DMC_RESEARCH.md) 和当前代码。没有继续训练或重启对局。

> 本文核对的是仓库内既定的“根先验混合”方案。用户随后明确指定 IJCAI 2021 的 AP-MCTS 论文；与那篇论文的逐项对照见 [AP-MCTS 论文对照](AP_MCTS_COMPARISON.md)。

## 确认对齐的部分

- `dmcMcts` 与 `guidedBehavior` 都使用 8 棵确定化树、原有树内 PUCT、线性 rollout、单轮终局回报及根访问比例聚合。每个真实决策双方均按 1,000 ms 总墙钟预算请求，观察和候选网络推理时间从搜索预算扣除。
- DMC 只读公开观察和手牌后验。编码的合法行动在原生入口逐项与 C++ 根行动校验。`npm run test:native` 通过 1,383 个局面的行动枚举和 rollout 校验；原生单元测试验证外部根先验在混合权重 0/1 时的实际安装。
- 15 场已完成比赛的 1,584 手已经独立重放，合法性、终局、胜负一致。它们是候选 7 胜、基线 8 胜；第 16 场按用户要求中断，不能当成完整配对结果。

## 与“新模型引导整个 MCTS”不对齐的地方

1. **新模型只在真实根节点调用一次。** `scripts/dmc-mcts-client.ts` 对合法行动评分后发送根概率；`cpp/mcts.hpp` 只在 `node == 0` 混入。所有树内非根节点仍使用旧线性先验，rollout 仍以旧线性模型贪心为主。因而这批 7:8 仅评价“旧搜索 + 50% DMC 根先验”，不评价 DMC 引导整棵树或模拟策略。
2. **优化目标不同。** DMC 回归的是自我对局策略下、行动玩家视角的**整场**胜负；MCTS 搜索回传当前**单轮**胜负。根先验虽然不直接与回报相加，但用整场 Q 重新分配单轮搜索的访问量，排序可能冲突。DMC 训练对手也与本次强搜索基线不同。
3. **先验变换未经校准。** 当前固定 `softmax(Q / 0.2)`，保留 5% 均匀质量，再与旧先验各占 50%。它不是概率校准所得，也没有按局面阶段或搜索预算调参。在已存对局抽取的 90 个候选决策局面，合法行动中位数 19，DMC 最大先验中位数 0.107、90 分位 0.301；说明强度随局面变化，不能把 50% 混合权重理解为稳定贡献 50% 的有效搜索指导。
4. **计时回退会改变算法身份。** 若 DMC 评分已经耗尽预算，`dmc-mcts-client.ts` 直接返回最高 Q 行动，完全不运行 MCTS。目前评测代码未统计该回退次数。本次 1 秒运行中没有逐决策计时汇总可证明回退为零；已完成对局仍能回放，但不应声称每手都执行了 MCTS。

## 下一步若继续这条研究线

先把根先验、实际搜索模拟数、截断数、模型准备耗时和纯 DMC 回退次数逐决策记录下来；比较同局面同隐藏世界下的旧先验、DMC 先验及混合先验。若目标确实是“DMC 引导整个 MCTS”，需要在树内节点和 rollout 中重建每条模拟路径的公开历史与手牌后验，再让 DMC 评分；不能直接把抽样世界的真实隐藏牌送入只用公开信息训练的模型。最后要明确对齐单轮还是整场回报，再用预先固定的配对种子评估。
