# MCTS + DMC 根节点先验试验

本试验使用千万样本训练后按 dev 选出的 `model-612.pt`，不重新训练网络。最终结果见 `evaluation-summary.json`；该文件只有全部预定评测结束并独立回放校验后才会生成。

## 已完成结果

| 配置          | 预算  | 对基线胜:负 | 融合版 / 基线平均完整决策耗时 |
| ------------- | ----- | ----------- | ----------------------------- |
| 50% DMC 先验  | 50 ms | 4:4         | 45.75 / 45.30 ms              |
| 100% DMC 先验 | 50 ms | 2:6         | 45.73 / 45.26 ms              |
| 50% DMC 先验  | 1 秒  | 2:2         | 959.71 / 945.96 ms            |
| 50% DMC 先验  | 2 秒  | 3:1         | 1889.73 / 1908.42 ms          |

全部 24 场比赛、2,492 次行动已独立回放：完整终局、动作合法、胜负与种子配对正确。2 秒组仅 4 场，有正向信号但不足以认定稳定提升；不同预算使用不同种子，不能从这个表证明预算增大带来更多融合收益。没有升版。

实际预算存在小幅超时：融合版 1 秒/2 秒最大约 1018.26/2010.72 ms；基线 2 秒组有一次 2054.87 ms，被记录为慢决策。完整耗时含观察、神经网络推理和搜索，不将 DMC 计算作为免费预算。

这次验证的是根先验融合。下一步应扩大配对种子数，使用同一组种子比较 1 秒与 2 秒，然后再单独评估价值头或 rollout 融合。不能把与先前纯 DMC 测试的差异直接归因于网络，因为那些测试使用不同种子，并且融合版本身增加了 MCTS。

## 方法

1. 在每个真实决策点，以原有 146 维公开观察、手牌后验、比赛印章和轮次信息，评分所有合法动作。
2. 把行动 Q 值转为实验性搜索先验：`0.95 * softmax(Q / 0.2) + 0.05 / 合法动作数`。这不是校准后的对手行为概率。
3. `dmcMcts`：根节点使用 50% 旧先验 + 50% DMC 先验。`dmcMctsPure`：根节点使用 100% DMC 先验。
4. 后续树节点、旧 rollout 策略、8 个隐藏世界采样、终局回报和根访问量决策沿用 `guidedBehavior`。
5. DMC 编码、推理与传输准备时间计入预算，MCTS 使用剩余时间。Torch 启动先预热。每次请求 C++ 验证动作覆盖完整且一一对应。

DMC 预测整场比赛回报，现有 MCTS 回传单轮终局结果；本次只将 DMC 用于先验，不将两种价值混合回传。全量 Q 转换不删除任何合法行动，也不做卖牌数量剪枝。

## 校验与边界

- TypeScript 编译通过；native 测试通过 1,383 个局面的动作枚举及 rollout 合法性校验。
- 新增测试验证混合权重为 0 时保持基线访问数，为 1 时准确安装指定动作先验。
- `scripts/verify-dmc-mcts.ts` 独立回放全部评测，检查合法动作、终局、胜负和种子配对。
- 本次没有把 DMC 接入 rollout：模拟中的公开历史后验需要正确更新，不能把完整隐藏状态直接送入网络冒充训练时的输入。
- 浏览器 Wasm 和默认 AI 没有切换至此实验。

复现：先 `node scripts/build-ai-research.mjs`，再设置 `JAIPUR_DMC_CHECKPOINT=analysis/dmc-10m-2026-09-24/model-612.pt`，运行 `node --experimental-strip-types scripts/benchmark-native.ts dmcMcts guidedBehavior 8201 2 1000`。配置名 `dmcMctsPure` 对应完全替换根先验。
