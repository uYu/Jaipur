# 斗地主行动空间方法调研与 Jaipur 分层搜索实验

## 一手资料与可迁移的部分

| 工作                                                                                           | 原方法                                                           | 对 Jaipur 的启发                                                 |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| [DouZero，ICML 2021](https://proceedings.mlr.press/v139/zha21a.html)                           | 将状态和动作一起编码，模型给合法动作计算 Q；用自我对局的回报学习 | 不必为每个组合设独立输出类别；货物数量、支付方式可作动作特征     |
| [DeltaDou，IJCAI 2019，§4.2](https://www.ijcai.org/proceedings/2019/0176.pdf)                  | 主策略输出牌型与点数，再由 kicker 网络和规则选择带牌             | 交换可拆成“换入目标”和“支付组合”，避免一层承受所有组合           |
| [Combinatorial Q-Learning，AIIDE 2020](https://ojs.aaai.org/index.php/AIIDE/article/view/7445) | 两阶段：选择手牌分解，再选要出的牌组；采用无序集合的池化表示     | 可以利用组合之间的共享结构，而不把每个完整组合视为互不相关的类别 |

已核对 [DouZero 模型实现](https://github.com/kwai/DouZero/blob/main/douzero/dmc/models.py)：每个候选得到标量价值，选最大者。其 [训练实现](https://github.com/kwai/DouZero/blob/main/douzero/dmc/dmc.py) 仍使用 MSE 回归回报。**训练损失可用 MSE，与仅凭验证集 MSE 选上线模型是两回事。** 它的 Monte Carlo 指回报学习，不应误说成每次决策运行现在这套 MCTS。

这些资料没有支持“持有五张就删掉所有少卖动作”的通用规则。斗地主以出完手牌为目标；Jaipur 有共享筹码、换货、驼队奖励和主动收市，不能照搬整手牌分解或只优先出最多牌。

## 本次落地：完整动作保留，分两层分配访问

新增 `SearchOptions.factor_actions`，实验配置为 `factored`，默认关闭。本次只借鉴分解思想，没有移植或重新训练上述论文的网络，也不声称复现它们的算法或成绩。

- 拿货：按货物种类分组；骆驼单独一组。
- 卖货：先选货物种类，组内选数量；所有数量从一开始都保留。
- 换货：先选拿入货物的数量向量，组内选付出的货物和骆驼。
- 第一层使用组的访问数和平均回报做 PUCT，第二层在组内选择完整动作。一次完整动作仍只消耗游戏中的一个回合，没有人为增加游戏回合。
- 组先验由组内最高动作先验归一化得到，组内再使用条件先验。这样同一目标不会因为支付方法多就自动分到更多先验质量。这是本项目的设计选择，论文没有为这个具体公式提供强度保证。
- 仅交换支付方式按先验排序渐进开放：最多开放 `1 + floor(sqrt(组访问数))` 个，直到全部开放。卖牌数量和单步拿牌从不因此隐藏。没有永久删除任何合法动作。
- 最终根节点仍按原方式汇总完整动作的访问占比；隐藏世界仍是八个。本次没有同时修改 rollout、奖励抽样、终局应对开关或根节点汇总，便于归因。

这种迁移也有风险：付款会改变市场、手牌和驼队，不能视为无关细节；先验差时，逐步开放可能延迟发现正确付款方式。组的平均结果也会受到组内早期差动作影响。它需要实战检验，不能仅凭分支数减少就升版。

这层分解还有一个结构上的界限：市场最多五张牌，拿入至少两张的子集最多 `C(5,2)+C(5,3)+C(5,4)+C(5,5)=26` 个；同类牌合并、骆驼排除和支付合法性检查会继续减少目标数。付款组合再多，也不会把交换目标这一层撑到超过 26 个。

## 固定局面与规则验证

1 秒搜索对比保存于 `fixed-1s.jsonl`，同一公开观测、八个世界和旧模型，仅分层开关不同。分层版在 2806 改为卖皮革；1309 两边此次都卖两皮革，1306 都卖两白银；3309、3801 没有改掉历史可疑动作；3701 改了交换组合但仍不卖。每配置每位置仅一次，墙钟搜索会有波动，不能冒充确定性的全部修复。

Native 测试通过：在原有 1,383 个合法行动测试局面中验证每个动作恰好归入一组、没有遗漏或重复、卖牌数量始终开放、充分访问后交换付款全部开放；另测先验归一化和分层选择。TypeScript 构建检查通过。

## 实验协议与复现

候选和基线都采用旧线性先验与 rollout、beta=0.75 公开手牌后验、八个世界，上一轮 `terminal_tactics` 实验开关两边都关闭。按完整三局两胜比赛评估，同一个种子交换先后手，观测耗时从预算中扣除。结果不与其他预算或之前实验混合计算胜率。

```sh
node scripts/build-ai-research.mjs
node --experimental-strip-types scripts/audit-rollout.ts factor 1000
JAIPUR_BENCH_LOG=/tmp/factored-games.jsonl node --experimental-strip-types scripts/benchmark-native.ts factored guidedBehavior 5101 6 50
```

`factored-*-games.jsonl` 保存完整事件；`factored-*-result.json` 保存逐局输出和最终统计。长预算样本仅用于初筛，不能作为可靠胜率估计。

## 后续选择

这次完成了动作分解的可运行迁移；尚未证明稳定变强。若继续训练，DouZero 更值得借鉴的是用实际可见信息与完整动作编码学习真实对局回报 `Q(o,a)`，而不是继续只模仿旧搜索的访问分布。它仍需自我对局迭代与独立配对验证；已有记录可以辅助启动，不能假定混合旧策略数据的回报就是最优动作价值。

此外，固定八个隐藏世界和跨树访问汇总仍保持原样，上一轮诊断的问题没有因此消失。要分别验证动作分解、动作评分和世界汇总，避免把几项改动一起打开后无法归因。
