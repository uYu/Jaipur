# JAIPUR · 粉城商事

仿照相邻 `scout` 项目的 React + TypeScript 分层结构与中文交互，实现的斋普尔双人桌游。你与本地 AI 商人米拉对弈，率先获得两枚卓越印章取胜。无需账号、后端或模型 API。

## 运行

Node.js 22.13+：

```bash
npm ci
npm run dev
```

默认地址为 http://127.0.0.1:5173。指定端口可使用 `npm run dev -- --port 5174`。

```bash
npm test                    # 规则、信息隔离、存档和完整比赛
npm run test:native          # C++ 完整行动枚举、rollout 合法性与终局选择
npm run simulate -- 100 hard # 100 场完整高难档 AI 对局
npm run tournament -- 5 1000 # MCTS 对重度档，5 个种子并交换先后手
npm run benchmark:ai -- 3 1000 /tmp/old-ai.mjs 30000 # 与备份的旧 Wasm 对比
npm run build:ai-research    # 编译训练、诊断及固定旧版基准（需要 Git 历史）
npm run train:ai             # 重训 100,000 轮，验证冻结权重逐字一致
npm run train:neural         # 需要本机 PyTorch/NumPy；重训并校验候选小网络
npm run diagnose:ai -- 400   # 配对比较同一局面不同首步及后续策略
npm run benchmark:timed -- guided old 1001 10 100 # 10 个种子换先手，每步约 100ms
npm run build:wasm          # 修改 C++ 后用 Emscripten 重建内嵌 Wasm
npm run build               # TypeScript 检查与生产构建
npm run preview             # 本地预览生产构建
```

从0启动PPO训练（Linux Docker，无需现有模型）：

```bash
docker compose --profile train up --build train
```

默认32768场，日志和检查点写入 `./training-runs/`，再次启动自动续训。配置、SwanLab及停止方式见 [容器训练说明](docs/TRAINING_DOCKER.md)。

Docker 部署：

```bash
docker compose up -d --build
# http://localhost:8204
# 修改端口：JAIPUR_PORT=8080 docker compose up -d --build
```

镜像使用 Node.js 22 构建静态资源，再由 Nginx 提供服务；生成的 Wasm 已作为跨平台 JavaScript 模块纳入源码，Linux 服务器构建镜像时不需要安装 Emscripten。镜像支持 Docker 提供的 amd64／arm64 平台，容器使用只读文件系统、`no-new-privileges`、临时 Nginx 缓存目录与 `/healthz` 健康检查。

```bash
docker compose ps                    # 查看健康状态
curl -fsS http://127.0.0.1:8204/healthz
docker compose logs -f jaipur
docker compose down
```

旧版 Docker Compose 也可使用 `docker-compose up -d --build`。

`dist/` 可交给任意静态服务器，支持子目录部署。图片为本地原创 SVG，无外部字体、图片或 API 请求。首次打开需要 HTTP 服务；未提供离线缓存 Service Worker，不支持双击 HTML 文件直接运行。

## 完整流程

- 中文主菜单、新比赛设置、继续比赛、规则、三档 AI、三档速度。
- 55 张牌与完整货物筹码、随机奖励筹码；开局保留三头市场骆驼、各发五张牌。
- 拿取单张货物、收走全部骆驼、至少两张的等量交换、单种货物批量出售。
- 7 张手牌上限，驼队独立；交换不能同时收付同类货物，不能通过交换获取骆驼。
- 钻石、黄金、白银至少两张起售；出售三／四／五张及以上获得对应奖励。
- 三类货物筹码耗尽或无法补满市场时结算。骆驼多数奖励 5 卢比，同数无人获得。
- 同分依次比较奖励筹码枚数、货物筹码枚数。完全相同时不颁印章，轮换先手加赛，这是规则书未明示极端平局的实现约定。
- 上轮输家先手；先获得两枚印章者获胜。最后一段行动动画结束后，自动在屏幕中央弹出本轮胜者、双方得分与印章结果，支持直接开始下一轮。整场结束有独立醒目提示、再来一场和返回菜单按钮；收起后牌桌顶部保留结算入口。逐轮战绩可展开查看，手机适配并支持键盘关闭。
- 对手手牌、驼队数量和奖励面值隐藏；对手公开货物收入可见。
- 无行动模式切换：点击市场货物拿取，点击同类手牌出售，两边选牌自动组成交换。点击市场骆驼选中全部；点击自己的驼队图案或加减按钮指定付出数量。再次点击取消，底部预览后确认。交换可任意顺序选牌。
- 开局从牌堆向双方发牌。每次行动直接在牌桌上移动卡牌：市场到手牌、手牌到售卖区、交换双向移动、牌堆补牌到市场并翻面，出售筹码从各自位置逐枚飞出，并排落入卖家收入区；分数旁保留上笔收入的每枚面值，刷新和回放也可查看。没有交易弹窗。对手收到的牌翻成牌背，奖励面值隐藏。展示结束后才允许下一回合；暂停、规则和日志会暂停展示计时，减少动态效果设置下改为静态展示。
- 暂停、规则、日志、菜单会终止 AI Worker；恢复后按当前状态重新计算。
- 桌面双栏牌桌；手机顶部吸附紧凑筹码栏，显示六类剩余数量、下一枚价值、奖励余量与售罄进度，完整筹码明细点开即看。滚动查看手牌时无需翻到页面底部查筹码。键盘可操作、弹窗焦点约束、减少动态效果支持。

## 存档与回放

每次**已提交行动**自动保存到 localStorage，刷新后由菜单继续；尚未确认的选牌不保存。新比赛会替换当前存档，开局设置页有提示。设置中可导出 JSON 或导入备份；导入按种子和完整行动序列逐步重放验证，损坏文件不会替换当前比赛。保存失败显示备份提示。

回放支持播放／暂停、单步和拖动进度，仅展示当时玩家可见信息，不启动 AI，也不写回比赛。难度偏好与 AI 行动速度独立保存在此浏览器。

## AI

当前算法的完整说明见 [AI 算法文档](docs/AI_ALGORITHM.md)。

DMC 自我对局、训练提速与续训，以及 MCTS 根先验融合的实验方法、数据、结果与复现入口见 [DMC 实验交接](docs/DMC_RESEARCH.md)；该候选尚未成为默认 AI。

AI 在 Web Worker 中执行，仅接收自己的手牌与驼队、双方公开收入、市场、公开弃牌与筹码、对手手牌数量、牌堆剩余数量和已提交的公开行动历史。不会接收对手真实手牌、对手秘密奖励、牌堆顺序或洗牌种子。

- 入门：TypeScript 轻量启发式，在合理行动间保留较多探索性，适合熟悉规则。
- 重度：C++/WebAssembly 战术穷举，枚举当前所有合法行动，评估兑现收益、成组潜力、驼队与收市风险。
- 高难：C++/WebAssembly 自对弈引导 MCTS，默认八棵树、约 1 秒墙钟时间预算，实际模拟次数随局面和设备变化。每棵树根据可见信息与公开行动历史采样一种可能的隐藏状态。一条边就是一次完整合法行动，交换按货物数量去重，拿取与支付一起生成。自对弈训练的轻量模型提供 PUCT 行动先验与后续模拟策略；一直模拟到本轮结算，按真实胜／负／平回传 +1／−1／0，通常按各树归一化访问次数选择。只有所有候选行动在采样中均告负时，才以模拟终局的平均分差选择损失较小的一步。

模型使用 140 个手牌数量、规则收益、驼队和游戏进度等特征，由固定种子下 100,000 轮 TD(λ) 自对弈学习权重。训练目标是归一化终局分差；模型仅指导如何搜索和如何继续走棋，不替代 MCTS 的真实终局胜负。没有“必须凑五张才卖”之类的硬规则。先验影响随访问增加而衰减，模拟策略保留 10% 随机探索。模型和特征仍带有归纳偏好，不是完全无偏的纯随机 MCTS。

模拟最多推进 256 手，超限只回传中性值，并单独计入截断数；搜索树另有 128 手保护上限。界面显示真实终局模拟次数及实际最大树深度，完整统计还包含截断次数和 rollout 总手数。

搜索预算统一定义在 `src/game/ai-config.ts`；游戏高难使用 1,000ms 时间截止，固定次数接口仍供测试和基准使用。八棵确定化树暂时保留，尚未改为 ISMCTS。比较新旧版本时应同时报告耗时与胜率，不能把一次终局模拟与一次旧版静态估值视为相同计算量。

三档均完全在本地运行；默认高难使用线性模型，不读取真实隐藏状态。固定模拟次数的搜索可复现；按时间停止时，设备和负载会影响实际模拟次数与最终行动。

### 实验神经网络

项目内已接入提供的 `tiny_nn.h`：保留其 NEON／AVX／标量 FP32 算子，并补上 Wasm SIMD128 后端及原位向量累加。当前实验模型使用 160 个特征和 64 个隐藏单元，是「原线性预测 + 双方差异与公共局面交互」的对称网络。交换双方玩家后估值严格反号，而不只靠数据增强逼近。训练使用 PyTorch，导出为纯 FP32 权重；游戏部署不需要 Python、PyTorch 或通用推理运行时。当前内嵌 Wasm 模块约 131KB；构建时启用 `-msimd128`。

训练流程按整局分开：固定种子的 12,000 局生成 88,789 个训练局面，另一种子 2,000 局生成 14,788 个验证局面；每个样本同时记录终局分差与胜负。随机交换玩家方位，使用 AdamW、验证集提前停止，并把旧线性模型的验证误差一同记录。数据缓存由生成器、状态特征和规则代码的摘要命名，相关代码变化后自动重新生成。`npm run train:neural` 重训并验证当前 64 单元胜负网络和 C++ 推理数值；可传 `--target margin`、`--architecture residual`、`--hidden 16` 做对照实验。只有对局证明更强后，才考虑将实验网络切为默认高难。详情见 `cpp/nn-training.json`。

默认高难仍使用上一版线性先验。想试玩 64 单元网络先验，可在本地地址加 `?ai=neural`；它使用相同的 MCTS 和线性模型后续模拟，只替换树搜索先验。独立验证集胜负均方误差从旧线性模型的 0.810 降到 0.673，且 C++ 与 NumPy 推理最大偏差低于 0.00001。模型并未经过真实信息集 MCTS 自对弈训练，训练局面来自完整的模拟世界。

64 单元网络全树先验与默认线性先验，在约 75ms/步的三组种子换先手对战中分别为 8:2、10:10、11:9；最后一组采用优化后的权重布局，平均 77.67ms 对 77.24ms，但网络侧只完成约 2811 万次终局模拟，对手约 3902 万次。胜率没有稳定超过默认线性版，不能宣称棋力提升。曾试用完整隐藏状态下 256 次 MCTS 产生行动排序标签，排序验证准确率达到 66%，实际 10 场却只有 1:9，因此撤回了这组训练权重和生成流程。探索系数 2.5 的两组比赛先后为 8:2、10:10，同样未修改默认值。

此前把原生等时基准每步搜索时间从约 78ms 增到 122ms 的 10 场试验为 4:6，没有观察到棋力收益。曾按用户要求把游戏高难提高到约 5 秒搜索；Node/Wasm 三个开局实测 5,006–5,032ms、43,504–51,792 次实际模拟。完整比赛另用相同的原生搜索程序比较：种子 22001–22010 换先手的 20 场，500ms 对 100ms 为 12:8，双方平均每步 483ms 对 102ms；种子 23001–23003 换先手的 6 场，5 秒对 1 秒为 1:5，实际平均每步 4.46 秒对 0.95 秒。缩时代理与真 5 秒赛方向相反，且后者样本很少；当前结果**不支持宣称 5 秒版胜率更高**，也不足以断言它稳定更差。两组不能合并成一个胜率；这些都是原生计时对局，不是浏览器 Wasm 的完整比赛。基于实测结果，游戏默认预算已恢复到约 1 秒，5 秒接口保留用于后续研究。

`tiny_nn.h` 的效率取决于部署后端。64 单元权重改为按特征排列，只对非零特征执行 SIMD 累加；相同权重下 Apple Silicon 原生完整局面估值约从 448ns 降到 211ns，Node 中 Wasm SIMD128 约从 719ns 降到 558ns。对应的稀疏线性估值分别约 15ns、54ns，所以大网络仍更贵。数字来自 `scripts/benchmark-tiny-nn.cpp` 的单机 30 万次微基准，仅说明估值开销，不代表完整 MCTS 提速或胜率。默认高难仍用更便宜的线性估值。

## 验证记录

当前版本原生测试覆盖 1,383 个局面，完整行动集合与独立枚举一致；校验随机及学习策略的合法性、卡牌守恒、特征优化实现与参考实现一致、交换玩家后的反对称性以及必胜终局出售。Wasm 定向回归检查持有三／四张皮革、市场还有两张皮革时选择继续拿牌，而非提前兑现。地址与未定义行为检测、生产构建均通过。

自动测试：原有 29 项完整套件通过（包括三档各 12 场比赛，共 36 场，逐步验证守恒和存档重放）；新增集牌回归单独通过，共覆盖当前 30 项测试。完整比赛测试使用固定每树 2,000 次模拟，本机约需 16 分半钟；游戏中的 1 秒时间预算不用于这些可复现测试。

初始 24,000 次终局模拟版本对旧高难 240,000 次静态叶节点评估，3 个种子交换先手的 6 场为 1:5；每手平均分别为 211 ms 和 758 ms，共 9,576,000 次模拟全部到终局。这个结果不支持“新版已经更强”的结论，也不是等时比较。当时的默认预算据此提高至 80,000 次；不以减少小批出售比例作为胜率提升的替代指标。

上一轮纯随机版本提高到 80,000 次预算后，对旧版四场仍为 1:3（平均 427ms 对 761ms）。配对诊断发现随机后续走法经常拆组、提前卖出，使搜索低估继续集牌的价值。因此当前版本转为学习后续策略，而非继续增加售牌禁令。

当前冻结模型对旧版（提交 `c86381e`）验证结果：

- 开发集：种子 101–104 交换先手，共八场，约 50ms/步，新版 8:0。
- 留出集：冻结模型后使用种子 1001–1010 交换先手，共二十场，约 100ms/步，新版 20:0；实际平均 101.82ms 对 101.03ms。两边只增加相同粒度的时间截止检查，不把模拟次数当作相同计算量。
- 当时的实际 Wasm：种子 1–2 交换先手，共四场，新版 4:0；当时默认 8,000 次终局模拟对旧版 240,000 次静态叶节点评估，平均 356ms 对 759ms。新版共 1,408,000 次模拟，全部到终局、截断为零。这组不是等时比较，也不代表当前按时间停止的版本。

胜率只针对固定旧版及这些种子，不代表对人类或其他策略的稳定胜率。固定八种隐藏状态、确定化搜索的信息泄漏偏差（模拟内部而非读取实际秘密）和简单线性模型仍有限制。小批出售本身可能合理，不以减少两三张出售次数代替强度验证。

训练种子 `20260922`，100,000 轮，后半程权重平均；冻结权重文件去除首尾空白后的 SHA256：`4364ed706927b5a18bfe3777d0a445f8ff54b0a77ab02e67a58c3e3787591248`。`npm run train:ai` 默认只验证，显式传入 `-- --write` 才更新权重；更新后需要重新构建研究程序和 Wasm。计时结果取决于本机负载，留出种子现在已经公开，后续调参不能再把它们作为新的独立留出集。

以下对战胜率为**改造前版本的历史记录**，不能用于描述新版强度：

- 29 项自动测试通过，其中完整比赛测试覆盖三档各 12 场，共 36 场；重度与高难档走实际 Wasm 内核。
- 每步检查 55 张牌、38 枚货物筹码、18 枚奖励筹码守恒及手牌限制；终局状态与存档重放一致。
- C++/Wasm 高难档在 64,000 次搜索预算下，使用 20 个相同种子并交换先后手，对旧普通档的 40 场基准为 30:10；样本用于回归比较，不代表稳定胜率。
- 将预算提升至 240,000 次后，定向复测上述 10 个失败局翻转了 6 局；单步基准约 0.8 秒。该结果不是重新跑完的 40 场总胜率。
- 同一 C++/Wasm 内核中的正面对局：64,000 次搜索预算下，MCTS 对原最高难度为 17:3；游戏采用的 240,000 次预算下，10 场复核为 8:2。两组均使用相同种子并交换先后手。
