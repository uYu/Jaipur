# Jaipur 当前 AI 算法说明

更新日期：2026-09-23。本文以仓库当前源码为准，重点说明游戏默认的**困难档**。文中的“胜率”“已知牌”和“模拟结果”分别有不同含义：搜索回传的是采样局面的终局胜负；已知牌只来自已提交的公开行动；一次模拟不是现实对局的必然结果。

2026-09-24 的 DMC 自我对局及 MCTS 根先验融合尚属研究候选；其方法、数据和当前结果单列于 [DMC 实验交接](DMC_RESEARCH.md)。

## 1. 游戏规则与 AI 的目标

一轮中，玩家轮流执行一个完整行动：拿一张货物、拿走市场全部骆驼、出售同类货物，或用手牌和骆驼交换至少两张市场货物。手牌上限为七张；钻石、黄金、白银每次至少卖两张。拿牌或拿骆驼后，从牌堆补市场到五张；交换与出售不补牌。第三类货物筹码售罄，或一次补牌后市场仍不足五张时，立即结算本轮。详见 [`engine.ts`](../src/game/engine.ts)。

结算分数 = 已获得货物筹码面值 + 奖励筹码面值 + 骆驼多数方的 5 分。骆驼数量相同则双方均无骆驼分。分数相同，依次比较奖励筹码数量、货物筹码数量；仍相同为平局。胜者获得一枚印章，先得两枚赢得整场比赛。**困难 AI 的 MCTS 只搜索当前这一轮的胜负**，没有显式搜索后续轮次或整场印章胜率。其终局回报从 AI 视角为胜 `+1`、平 `0`、负 `-1`。[`cpp/jaipur_ai.cpp`](../cpp/jaipur_ai.cpp) 中的 C++ 规则模拟与前端规则对应。

各类牌总数分别为钻石 6、黄金 6、白银 6、丝绸 8、香料 8、皮革 10、骆驼 11。货物筹码从高到低领取，奖励筹码按出售数量分 3、4、5 张及以上三档，档内面值隐藏并洗牌。数值定义见 [`data.ts`](../src/game/data.ts)。

## 2. 三档 AI 与运行入口

| 游戏档位 | 实际执行 | 决策依据 |
| --- | --- | --- |
| 入门 | TypeScript，`chooseAction(..., "easy")` | 枚举合法行动，比较即时收益、手牌潜力、骆驼价值和风险，加入较大的确定性伪随机扰动。 |
| 重度 | C++/Wasm，`jaipur_choose_original` | 枚举当前合法行动，作一层启发式打分，加入少量局面规则和很小的扰动。源码函数虽然叫 `choose_original_hard`，**目前在游戏中对应重度档**。 |
| 高难／困难 | C++/Wasm，`jaipur_choose_timed` | 公开记牌 + 隐藏状态抽样 + 八棵由线性自对弈模型引导的 MCTS 树。默认使用约 1 秒时间预算。 |

界面在 AI 回合由 [`App.tsx`](../src/App.tsx) 建立 Web Worker，传入观察和难度；[`ai.worker.ts`](../src/game/ai.worker.ts) 按难度调用以上实现。搜索在 Worker 中运行，不阻塞页面。用户设置的行动速度只控制动画／落子等待，**不改变搜索预算**。保存的对局难度优先于当前菜单偏好。

在网址加 `?ai=neural` 时，困难档改调用实验性的 `jaipur_choose_neural_timed`：**只替换搜索树的行动先验为神经网络，后续模拟仍使用默认线性策略**。该开关不是默认设置；第 10 节单独说明。

## 3. AI 看见什么、怎样记对手牌

每次决策生成一次 [`Observation`](../src/game/ai.ts)：AI 自己的货物手牌和骆驼数、自己已获得的货物与奖励面值、对手公开的货物筹码收入及数量、市场五张牌、各类剩余货物筹码、各档剩余奖励筹码数量、公开弃牌、牌堆张数、对手货物手牌张数、回合手数，以及从行动历史推出的对手已知货物牌。传给 Wasm 的数据没有对手真实手牌、对手秘密奖励面值、牌堆顺序或洗牌种子。

对手已知手牌由 [`publicOpponentKnowledge`](../src/game/ai.ts) 按本轮公开事件重放得到：

1. 对手从市场拿某货物：将该牌加入已知集合。
2. 对手交换：移除其中已知的付出货物，加入从市场拿走的货物。付出的牌和拿走的牌都是公开行动内容。
3. 对手出售：从已知集合中移除相应数量的该类货物。
4. 新一轮发牌：清空上一轮的记牌结果。

初始发到对手手里的牌未知。某张后来拿过的牌如果已被出售或换出，也不再算已知。由于同类牌没有个体身份，记忆是**各货物的确定下界**，不是对手整手牌的完整预测。没有可用行动历史时，这个下界为空。驼队和未公开抽牌按牌数守恒处理，不被当成“亲眼看见”。

## 4. 从可见信息抽样隐藏状态

每棵搜索树先在 [`determinize`](../cpp/jaipur_ai.cpp) 中采样一个与观察一致的完整世界。对每种货物 `g`：

```text
未知库存[g] = 总牌数[g]
            - 我方手牌[g] - 市场[g] - 已弃牌[g] - 已知对手手牌[g]
```

算法打乱这批未知货物，先补足对手剩余未知手牌，再把其余货物和未知骆驼分配到牌堆。对手的骆驼数通过牌数、市场骆驼数、我方骆驼数、对手货物手牌数和牌堆张数推得。对手已经领取的秘密奖励面值，则从每档奖励面值池扣除我方已知面值，再按公开的剩余数量随机分配；余下成为模拟中的奖励堆。货物筹码的公开剩余顺序直接沿用观察值。

因此，“AI 猜对手牌”具体是：**已知部分固定，未知部分从剩余牌均匀打乱分配**。没有按对手以往打法推断偏好，也没有对“对手故意留某种牌”做贝叶斯更新。每棵树内部把这一套采样当作真实局面，下一棵树重新采样。采样的隐藏牌只是搜索假设，不会写进真实游戏状态。

搜索随机种子由编码后的观察计算哈希；固定观察与固定迭代次数可重现决策。按时间截止时，设备负载改变实际迭代量，行动未必完全相同。

## 5. 完整合法行动空间

困难档的 [`atomic_actions`](../cpp/mcts.hpp) 按货物**数量组合**去重，而不是给同类实体牌的每种排列都建一个分支：

- **拿货物**：手牌不足七张时，可拿市场中任一货物种类的一张；相同种类只生成一个候选。
- **拿骆驼**：市场有骆驼时，一次拿走全部骆驼。
- **出售**：普通货物可卖 `1…手中数量`，三种贵重货物可卖 `2…手中数量`；即使某类货物筹码已经卖空，规则仍允许卖出。
- **交换**：从市场取至少两张货物，按货物种类和数量枚举所有组合；再枚举用我方货物与骆驼支付的所有合法组合。取和付的货物种类不能重叠；支付骆驼数量不能超过驼队；交换后手牌不能超过七张。

一条搜索边恰好是一手完整行动。市场越多货物、我方手牌和骆驼越丰富，交换候选越多；这会明显增加搜索分支与评估开销。Wasm 把选中行动的种类和货物数量编码返回；[`ai-wasm.ts`](../src/game/ai-wasm.ts) 再按当前市场和手牌中的索引还原给前端规则引擎执行。

## 6. 困难档搜索全过程

```mermaid
flowchart LR
  A[公开观察和行动记忆] --> B[采样 8 个隐藏世界]
  B --> C[每个世界独立建 MCTS 树]
  C --> D[树内选择、扩展、模拟至结算]
  D --> E[回传真实终局胜负]
  E --> F[各树根访问比例合并]
  F --> G[选择当前行动]
```

默认参数在 [`ai-config.ts`](../src/game/ai-config.ts)、[`SearchOptions`](../cpp/mcts.hpp) 中：8 棵树，总名义预算 1,000 ms，探索系数 `√2`；每棵树分配总预算的八分之一。定时 API 还设有每棵最多 100,000 次迭代的安全上限，**实际次数由耗时决定，绝非固定 100,000 次**。另一个固定次数 API 默认每棵 1,000 次，主要供测试与基准使用。时间检查每 16 次迭代执行一次，因此 1,000 ms 不是严格的硬截止。

每棵树的每次迭代：

1. 从该树采样的根局面复制状态，沿树走下去。
2. 第一次进入某节点时生成全部合法行动，并对每个行动的下一局面作一次模型估值，转换成行动先验。
3. 以 PUCT 选择行动；当前轮到对手时，将根玩家视角的平均回报取反。走到首次访问的边后停止树内选择；已访问的边继续向子节点走。树内深度最多 128 手。
4. 从停止处以模拟策略继续走到本轮结算，或最多再走 256 手。真实结算回传 `+1/0/-1`；模拟超限回传 `0`，并记入截断数，**不会把未结算手牌估值伪装成胜局**。
5. 沿本次走过的边累加访问次数、终局胜负和终局分差。下一迭代继续利用这些统计。

对于节点中的行动 `a`，设 `N` 为节点访问次数，`n_a` 为该边访问次数，`Q_a` 为该边从根玩家视角的平均终局回报，`P_a` 为先验概率，则默认选择分数为：

```text
当前玩家是 AI：    Q_a + √2 · P_a · √(N + 1) / (1 + n_a)
当前玩家是对手： -Q_a + √2 · P_a · √(N + 1) / (1 + n_a)
```

初始 `P_a` 来自“执行 `a` 后局面”的单步线性估值。先把估值转为行动者视角，再按同一节点的最高值和极差变换：

```text
raw_a = exp(4 · (value_a - maxValue) / max(0.05, maxValue - minValue))
P_a   = raw_a / Σ raw_b
```

这样所有合法行动都有非零先验；先验只是引导访问，随 `n_a` 增加影响下降。默认没有启用 progressive widening；节点会生成全部合法行动。对手在搜索树中同样按其视角选择高价值行动，但树只对应一套采样的隐藏牌，**并非真正的信息集搜索**。

## 7. 线性模型与后续模拟

默认线性模型见 [`rollout-policy.hpp`](../cpp/rollout-policy.hpp) 和 [`rollout-weights.hpp`](../cpp/rollout-weights.hpp)。它从 AI 玩家 0 的视角估值：70 个基础特征，加上这 70 个特征各自乘以游戏进度，共 140 个。基础特征包括：当前双方已兑现分数差、当前行动者、每种货物手牌 1 至 7 张的数量指示、按当前筹码可立即卖出的收益、可获得奖励档位的期望值、骆驼数量、已获奖励与货物筹码数、骆驼多数状态。进度定义为 `1 - min(40, 牌堆张数) / 40`。基础部分和进度交互部分分别用训练权重加权，最后经过 `tanh`，落在 `[-1,1]`。终局状态不调用近似模型，而直接返回规则结算的胜负值。

训练程序 [`train-rollout.cpp`](../scripts/train-rollout.cpp) 在固定种子 `20260922` 下自对弈 100,000 轮，使用 TD(λ)：资格迹衰减系数 `0.7`、基础步长 `0.04`、按特征范数归一化；训练行动有 15% 随机探索。训练终局目标为分差除以 `224`，并平均后半段训练权重。结果作为常量编进 Wasm，游戏运行时**不在线学习**。这是一个估值模型，不是显式棋谱、硬编码的“凑五张再卖”规则或完美终局求解器。

每次 MCTS 后续模拟，90% 概率由线性模型对**全部合法下一行动**做一层估值并选最高者，10% 概率走随机行动生成器。随机生成器先选可用行动类别，再选类别内动作；交换用随机卡牌子集提案与拒绝采样。模拟双方使用同一套策略。搜索边的回传值始终来自最后的规则结算，模型只影响先验和模拟路径。

## 8. 八棵树如何合并、必输时如何处理

一棵树结束后，对其根节点每条行动的访问次数除以该树根总访问次数；八棵树把相同行动的比例相加。**一般情况下选合并访问比例最高的行动**；若相同，再比其模拟平均胜负。这里的“访问支持率”是被选行动获得的八树归一化访问份额，**不是胜率或可信概率**。

另有一条很窄的兜底：只有聚合的**每一个**根候选都得到过访问，且它的所有已采样结果均为失败 `-1`，才改按模拟终局平均分差排序，优先少输分。分差经 `tanh((我方分数-对手分数)/20)` 压缩。这个兜底不会在“看起来落后”时自动启动；只要存在未访问的根行动、平局或胜局样本，就仍按访问次数选择。因此它不是通用的落后局面策略，也不是风险控制器。具体实现见 [`mcts.hpp`](../cpp/mcts.hpp) 中 `choose`。

搜索结果和统计由 [`jaipur_ai.cpp`](../cpp/jaipur_ai.cpp) 输出，前端显示树数、模拟数、根行动数、访问支持率、交换候选数、真实终局模拟数、最大树深和耗时。`simulations` 包括正常结算与 256 手截断的模拟；“每棵迭代”在定时模式下是实际总模拟数除以八后的整数展示值。

## 9. 重度与入门档的打分细节

重度档的 C++ 单步分数主要为：

```text
即时卖货收入 + 卖货奖励期望
+ 行动后手牌潜力 - 行动前手牌潜力
+ 行动后驼队价值 - 行动前驼队价值
- 拿骆驼或交换的风险项
+ 少量局面修正和极小伪随机扰动
```

手牌潜力按可兑现货物筹码与奖励期望估计，并对孤张贵重货物、接近手牌上限等做折减。骆驼价值前四头每头权重 `1.25`，接下来三头每头 `0.3`。重度档还额外考虑第三类筹码即将售罄时出售导致提前结算的风险；牌堆偏少时提高出售收益；轻微偏好拿贵重货物、折价交换，并在牌堆很少时稍增拿骆驼的价值。详见 [`choose_original_hard`](../cpp/jaipur_ai.cpp)。这些都是**局部静态估值**，不会像困难档那样抽隐藏牌并模拟后续对局。

入门档在 [`ai.ts`](../src/game/ai.ts) 中使用相近的即时收益、潜力、骆驼和风险估计，但扰动幅度更大，且没有重度档所有局面修正。入门和重度档的随机扰动由局面相关种子生成，目的是打破静态评估的固定偏好。

## 10. 实验神经先验

实验模型见 [`neural-policy.hpp`](../cpp/neural-policy.hpp)、[`nn-weights.hpp`](../cpp/nn-weights.hpp) 与 [`nn-training.json`](../cpp/nn-training.json)。它使用 140 个线性模型特征，再加市场、剩余货物／奖励筹码、牌堆、双方手牌数等 20 个特征，共 160 个；对称结构有 64 个隐藏单元。网址 `?ai=neural` 仅令搜索节点的 `P_a` 使用该模型。搜索深度、终局回传、八树聚合和 90% 线性／10% 随机的模拟策略仍与默认困难档相同。

验证集的胜负预测均方误差比线性模型低，**不能据此认定实战更强**。研究日志 [`analysis/ai-eval-2026-09-23`](../analysis/ai-eval-2026-09-23/README.md) 中的 5:35 是“神经先验**加神经模拟策略**”对线性默认版、原生程序每步名义 50 ms 的比赛；它不是网页 `?ai=neural` 这个只换先验配置的直接战绩。默认仍为线性模型。

## 11. 当前已知局限与复盘时的读法

1. **隐藏牌只抽八套。** 罕见但致命的对手组合可能只进入一棵树，甚至一次都没抽到；公开已知牌虽固定，未知牌风险仍会被有限采样低估。
2. **每棵树固定一套隐藏世界。** 模拟里的对手可以按该世界的完整牌行事，搜索不是 ISMCTS，也未在对手节点对不同可见信息做信息集约束。
3. **后续策略是学习后的一层贪心。** 如果该策略在某类局面中偏爱换牌、延迟出售或误估收市风险，模拟就会系统性偏向这种后续；多做模拟也不一定能消除模型偏差。
4. **根节点用访问比例决定行动。** 它不是对每个候选做相同样本、相同计算量的严格胜率对照，也没有“对手下一手可能立即结束”时强制先卖的规则。因此，出现“我拿两张、对手一手收市，AI 却换骆驼”的行动，与当前机制并不矛盾。
5. **必输兜底触发严格。** 未访问候选会阻止兜底；它只解决所有根行动采样都必输时的排序问题，不能修复本可赢却被采样或模拟策略遗漏的行动。
6. **模型优化目标与整场胜率不同。** 线性权重用归一化本轮终局分差训练；MCTS 回传本轮胜负；真实比赛以先拿两枚印章取胜。它没有明确建模整场比分、不同对手风格或风险偏好。
7. **实验数据要按版本和预算解释。** [`扩样报告`](../analysis/ai-eval-2026-09-23/README.md) 的 20:0 是当前整套线性引导搜索对固定旧提交 `c86381e` 的 20 局成绩，原生程序每手名义 50 ms。它不能归功于某一条近期微调，也不能直接当成浏览器 1 秒 Wasm 的胜率。

复盘一手棋时，建议同时记录：当前公开信息、已知对手牌、AI 的候选行动与实际选择、当时搜索统计、真实对手下一手，以及**仅替换这一手**的反事实结果。反事实必须注明它是否固定了实际隐藏牌和对手后续；固定后的反事实能证明该条记录下的得失，但不能证明未知世界中同样必胜。
